# Draft a reply

## When to use

Any time the person wants help answering an email: they paste in a thread, forward a message, or point at something in a connected inbox and say "reply to this" or "what should I say to Priya".

## What you need

- The email thread itself, either pasted in or read from the connected inbox (check context/tools.md for what you're allowed to do there; default is read and draft only).
- context/people.md, to understand the relationship and how formal to be.
- context/voice.md, used by write-like-me, so the draft sounds like the person, not like a generic assistant.

## Steps

1. **Read the whole thread**, not just the latest message. Work out what's actually being asked, which might be different from what's on the surface. A question buried in paragraph two still needs answering.
2. **Check context/people.md** for who this is. Are they a client, a supplier, a long-standing contact, someone new? That decides the formality and how much explanation is needed.
3. **Work out if a key fact is missing.** A price, a date, a yes or no decision only the person can make. If one genuinely blocks the reply, ask exactly one question before drafting. Don't ask more than one; guess sensibly at anything smaller and flag the guess in your reply to the person.
4. **Draft the reply** using write-like-me (their voice) and then human-email's rules and checklist. Answer the actual question first, no recap of their email, no padding.
5. **Offer one shorter alternative** when the full draft runs long or when there's a plainly quicker way to say the same thing. Show both; let the person pick.
6. **Offer to save it as a draft in their inbox**, if the connected email tool supports drafts (check context/tools.md). Never send it. The person reviews and sends it themselves.
7. **Spot any follow-up work the reply creates.** If the reply promises something ("I'll send the file Thursday", "I'll check with the supplier"), offer to add it to the task list as a suggestion, following the task list's rules: mark it suggested, with addedBy claude and a source noting it came from this email thread.
8. **Present the draft plainly**: who it's to, what it says, and that it's ready to review and send.

## Rules

- Never send an email. Draft only, every time, no exceptions.
- Ask at most one clarifying question, and only if the reply genuinely cannot be written without it.
- Always run the human-email checklist before showing a draft.
- Don't invent facts (a price you don't know, a date nobody gave you). Leave a clear gap and ask, or flag it as something the person needs to fill in before sending.
- If the thread includes something sensitive (a complaint, a dispute, bad news), say so and suggest the person reads the draft carefully before sending rather than rushing it out.

## Examples

**Short, simple thread.** Tom at Greenway Café emails: "Can you do the catering for Saturday the 14th, same as last time, for about 30 people?" A full key fact (date, numbers) is already there, so draft directly: "Hi Tom, Saturday the 14th works, and 30's a comfortable number for us. I'll send the same menu as last time unless you want changes. Can you confirm numbers by Wednesday so I can order in? Speak soon."

**Thread missing a key fact.** Hollins Lettings asks about doing a job "sometime in the next couple of weeks" with no date given and no indication of urgency in context. Ask: "Do you have a date in mind for the Hollins Lettings job, or should I suggest one?" Then draft once you have it.

**Thread that creates a follow-up.** A reply promises to send an updated quote by Friday. After drafting the reply, say: "This reply promises an updated quote for Marlow Dental by Friday. Want me to add that to your task list?"

## If something is missing

If context/people.md doesn't cover this contact yet, say so and use a plain, moderately formal default, then suggest adding them to context/people.md so future drafts get the formality right automatically. If context/voice.md is empty, mention that write-like-me's learn mode would make replies sound more like the person specifically, and draft with the plain human default in the meantime.
